# UBERVZLA Driver v0.8 — base de integración (NO lanzamiento comercial)

Esta rama de desarrollo reemplaza las aprobaciones ficticias por una barrera de servidor. No es una versión final ni debe sustituir el servicio de prueba actual. Instalar en otro repositorio/servicio de desarrollo y conservar v0.7.5 para pruebas aisladas. Por defecto no acepta registros/documentos ni viajes, retiros o aprobaciones. No activar `UBERVZLA_INTAKE_ENABLED` con datos reales hasta terminar la revisión de seguridad y privacidad, pruebas y validación de infraestructura. El código de recepción de archivos es preliminar: comprueba tamaño y encabezados, cifra con Fernet y requiere una ruta /var/data; eso no confirma que el volumen sea persistente ni que los archivos sean seguros. Faltan escaneo, control de acceso administrativo detallado, auditoría, retención/borrado, protección de intentos, MFA administrativo, aviso legal, restauración, recuperación de cuentas y revisión de seguridad. No se verifican documentos ni rostros. La cámara solo captura una fotografía. Las passkeys de la rama previa están conservadas en el servidor pero sus endpoints están bloqueados en esta rama. No se habilita un trabajador por revisar una solicitud. No usar datos personales reales ni dinero.

Archivos: app.py, driver.html, admin.html, requirements.txt. La página principal está incluida en app.py. Build: pip install -r requirements.txt. Start: uvicorn app:app --host 0.0.0.0 --port $PORT. Para servicio de desarrollo con otro dominio, adaptar la constante PASSKEY_ORIGIN antes de ejecutar flujos autenticados. /health, /driver y /admin son las rutas principales. La base SQLite usa un nombre independiente (foundation.db) para no migrar las cuentas ficticias. No conectar la base de pruebas anterior.

Pendiente para producción: proveedor autorizado de identidad y prueba de vida + comparación 1:1; SMS +58 y email verificables; antecedentes y documentos mediante revisión legítima; WebAuthn con autenticación y recuperación de cuenta reales; flujo de aprobación por evidencia con acceso restringido; base persistente con copias y seguridad; tarifas, pagos y retiro con proveedor y libro mayor; pruebas en dispositivos y autorización legal. Luego separar Viajes, Delivery y Comercios sobre la API central. No habilitar el motor de operaciones hasta completar dichos controles.


## v0.8.1 — soporte e invitaciones privadas
Se incluye support.html: asistente guiado de preguntas frecuentes, local al navegador, sin IA externa ni envío de conversaciones. Configurar UBERVZLA_SUPPORT_EMAIL con el correo oficial para mostrar un enlace de atención humana. No se crea un ticket ni se confirma el envío.
El registro exige invitaciones de un solo uso. Generar códigos aleatorios de alta entropía con generate_invites.py en un entorno privado. Configurar únicamente sus hashes en UBERVZLA_INVITE_HASHES (separados por comas); entregar cada código personalmente al aspirante cuando se autorice la beta. Nunca subir secretos a GitHub. No compartir códigos en chat. El uso se registra en la base de datos con una restricción única.
IMPORTANTE: UBERVZLA_INTAKE_ENABLED debe seguir desactivada hasta validar almacenamiento persistente, revisión de seguridad, protección de datos y los requisitos legales. Las invitaciones no sustituyen autenticación ni las verificaciones. Este paquete no habilita viajes, aprobación, retiros ni biometría real. Instalar en entorno de desarrollo separado, no sobre v0.7.5.
